# پرامپت فرانت‌اند SMS Automation سوکانکس

در React فعلی سوکانکس یک صفحهٔ RTL و واکنش‌گرا در `/admin/sms-automation` بساز. از AuthProvider و API client/JWT refresh موجود استفاده کن؛ هیچ منطق OTP، ورود یا اعلان‌های فعلی را تغییر نده. لینک سایدبار فقط وقتی `GET /api/dashboard/` در `data.capabilities.can_manage_sms_automation` مقدار `true` دارد دیده شود. خود route نیز محافظت شود، اما مجوز اصلی را Backend اعمال می‌کند. برای کاربر 401 به ورود و برای 403 به صفحهٔ عدم دسترسی برو. هیچ credential پیامیتو یا API key را در فرانت ذخیره یا نمایش نده.

Base URL همان API فعلی اپ است: `https://api.sokanex.com`. مسیرها همگی زیر `/api/notifications/sms-automation/`:

1. `GET status/`: نوار وضعیت با `automation_enabled`, `provider_configured`, `market_access_v2_enabled`, `enabled_rules`, `pending`, `needs_reconciliation`. اگر automation یا provider خاموش است هشدار واضح نشان بده، بدون حدس‌زدن کلید API. `needs_reconciliation>0` را با هشدار «ارسال نامشخص؛ قبل از تکرار با اپراتور بررسی کنید» نشان بده.
2. `GET rules/`: تب «سناریوها». ruleها را با event و بازار دسته‌بندی کن: Welcome، تغییر دسترسی، Trial روزهای ۱/۳/۵/۶/۷ و بازارهای ALL/internal/forex/crypto. هر rule یک فرم `PATCH rules/{id}/` برای `text`, `enabled` و زمان داشته باشد. Trial: `trial_day` ۱..۷ و `send_time_utc` `HH:MM:SS` (واضح بنویس ساعت UTC؛ برای ایران +03:30 تبدیل نمایشی کن ولی مقدار ارسالی UTC باشد). Welcome/Access Change: `delay_minutes` ۰..۱۰۰۸۰؛ `trial_day` و `send_time_utc` را برایشان نفرست. برای Trial، `delay_minutes` را نفرست. تغییر rule فقط روی ارسال‌های آینده اثر دارد. نسخهٔ بازار مشخص اگر روشن باشد روی ALL اولویت دارد.
3. ویرایشگر متن حداکثر ۵۰۰ کاراکتر با شمارنده و دکمهٔ درج متغیرهای مجاز `{first_name}`, `{last_name}`, `{days_remaining}`, `{support_link}`, `{membership_tier}`, `{market_name}` بساز. متن خام به‌صورت React text نمایش داده شود، نه `dangerouslySetInnerHTML`. HTML و متغیر دلخواه را ممنوع کن، اما منبع نهایی validation خود API است. برای Trial یادآوری کن متن هر روز و هر بازار مستقل است.
4. تب «ارسال گروهی»: انتخاب چندتایی tierهای محاسبه‌شدهٔ V2 `LEVEL_1`, `BASIC`, `PRO`, `GOLD`, `ELITE` و یک بازار `ALL/internal/forex/crypto`، سپس متن. ابتدا فقط `POST broadcasts/preview/` با `{membership_tiers,market,text}` بزن. `eligible_count` و هشدار هزینهٔ پیامک را در modal تأیید جداگانه نشان بده. تا کاربر تعداد مخاطبان و هزینه را تأیید نکرده، هرگز `send/` را نزن. برای ارسال `POST broadcasts/send/` با همان سه فیلد + `expected_eligible_count`, `expected_candidate_digest`, `idempotency_key` پایدار (یک UUID/رشتهٔ تصادفی ۸ تا ۶۴ کاراکتری برای همان کلیک)، `confirm:true`. هنگام انتظار دکمه را قفل کن؛ در retry شبکه همان idempotency_key را دوباره بفرست، کلید تازه تولید نکن. ۲۰۱ یا ۲۰۰ یعنی «در صف قرار گرفت»، نه تحویل شده. 409 `AUDIENCE_CHANGED` باید پیش‌نمایش مجدد بخواهد؛ 409 `IDEMPOTENCY_CONFLICT` خطای کلید تکراری است. اگر قابلیت خاموش یا V2 خاموش است فرم ارسال غیرفعال باشد.
5. `GET broadcasts/`: تب تاریخچهٔ کمپین‌ها با تعداد مخاطب، متن، بازار و زمان. فقط نمایش؛ endpoint حذف/ویرایش برای آن وجود ندارد.
6. `GET deliveries/?page=&page_size=&status=&event=&user_id=&search=`: تب «گزارش ارسال» با pagination سروری، فیلتر وضعیت/رویداد و جستجوی نام کاربری یا موبایل. ستون‌ها: کاربر، شماره، متن رندرشده، زمان برنامه‌ریزی، زمان ارسال، وضعیت و کد خطا. `PENDING`, `SENDING`, `SENT`, `FAILED`, `SKIPPED` را متمایز نشان بده. برای `SENDING` قدیمی دکمهٔ retry خودکار نساز؛ امکان ارسال تکراری وجود دارد. متن کامل پیام فقط در این صفحهٔ superadmin نمایش داده شود.

ظاهر با پنل مدیریت فعلی و RTL هماهنگ، موبایل‌پسند، و دارای حالت‌های loading/empty/error باشد. پاسخ‌های خطای پروژه ممکن است داخل `errors`/`detail`/`message` باشند؛ پیام خوانا نشان بده. از دادهٔ ساختگی برای وضعیت ارسال، مخاطبان یا تنظیمات استفاده نکن. API باید از endpointهای واقعی خوانده شود. فرانت فقط ویرایش و درخواست مدیریتی انجام می‌دهد؛ زمان‌بندی، تشخیص Trial/سطح و ارسال پیامیتو همگی در Backend هستند. تست‌های فرانت برای gate capability، فرم هر نوع rule، تبدیل ساعت UTC، پیش‌نمایش و تأیید، حفظ idempotency key در retry، 409 و pagination گزارش بنویس.

قرارداد دقیق Backend و راهنمای استقرار در `docs/sms-automation-fa.md` است. تا قبل از فعال‌سازی آگاهانهٔ `SMS_AUTOMATION_ENABLED=True` در Gunicorn و worker و روشن‌کردن ruleها، هیچ SMS Automationی ارسال نمی‌شود.
